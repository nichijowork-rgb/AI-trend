# AI版 収集botへの依頼書（AI-trend）

> この文書をそのまま収集botの担当者に渡してください。
> X-trend（夜職版）と**同じ形式**の JSON を、新しいリポジトリ `nichijowork-rgb/AI-trend` の `data/` に毎日 push してもらう依頼です。

---

## 1. お願いしたいこと

X の **AI 関連の投稿**と**医療・介護の投稿**を定期的に集めて、カテゴリを付け、次の 3 ファイルを `nichijowork-rgb/AI-trend` リポジトリの `main` ブランチ、`data/` フォルダに push してください。

| ファイル | 必須 | 内容 |
|---|---|---|
| `data/posts.json` | 必須 | 投稿一覧（X-trend と同じ形式） |
| `data/summary.json` | 任意 | 集計（X-trend と同じ形式） |
| `data/reports.json` | 任意 | 伸びている投稿・答え合わせ・的中率・週間まとめ（X-trend と同じ形式） |

- 画面（`index.html`・`assets/`）はこちらで管理します。**bot は `data/` 以外を変更しないでください。**
- push の権限は、リポジトリのオーナー（nichijowork-rgb）から付与します（Deploy key か collaborator 招待。どちらがよいか教えてください）。

## 2. データの形式（X-trend と同じ）

- `posts.json`: `{ generated_at, categories[], posts[] }`
  - Post: `id`（**文字列**）/ `url` / `user` / `created_jst` / `ts`（UNIX秒）/ `metrics`{impression_count, like_count, retweet_count, reply_count, quote_count, bookmark_count} / `text` / `categories[]` / `matched_terms[]` / `is_watched` / 任意で `media[]`
- `summary.json`・`reports.json`: X-trend と同じキー名・同じ構造でお願いします（詳しくは [DASHBOARD.md](DASHBOARD.md) の「データ側botとの取り決め」「レポート欄」）。
- 分からない数値は `null` のままで構いません（画面に「不明」と出ます。0 で埋めないでください）。

## 3. カテゴリ（ここだけ X-trend と違います）

画面は［AI｜医療］の 2 つに切り替えて見ます。カテゴリ名は**この文字列のまま**（全角・中黒・×も同じ）でお願いします。

**AI 側**

| カテゴリ名 | 内容 | 収集キーワードの例 |
|---|---|---|
| `新モデル・発表` | 新しいモデルやサービスの発表・アップデート | Claude、ChatGPT、GPT-5、Gemini、Llama、新モデル、リリース |
| `ツール・活用` | 使い方・プロンプト・業務での活用術 | 生成AI 活用、プロンプト、AIエージェント、自動化、Claude Code、Cursor |
| `研究・論文` | 論文・ベンチマーク・技術解説 | 論文、arXiv、ベンチマーク、LLM、推論、マルチモーダル |
| `ビジネス・業界` | 資金調達・規制・導入事例・業界ニュース | 資金調達、AI規制、AI法、導入事例、業務効率化 |
| `AIその他` | 上のどれにも当てはまらない AI の話題 | AI、AIニュース、AIイベント、勉強会 |

**医療 側**（AI に限らず、医療・介護全般）

| カテゴリ名 | 内容 | 収集キーワードの例 |
|---|---|---|
| `医療・介護×AI` | **重点**。医療・看護・介護での AI 活用（**AI 側にも医療側にも出ます**） | 医療AI、介護DX、訪問看護 AI、看護記録 AI、電子カルテ 生成AI、AI問診、医療DX |
| `訪問看護` | 訪問看護・在宅医療の話題 | 訪問看護、訪看、訪問看護ステーション、在宅医療、在宅看護 |
| `医療ニュース` | 病院・医師・感染症など医療全般のニュース | 病院、医師、看護師、感染症、医療費、医療ニュース |
| `介護・福祉` | 介護現場・福祉・人材の話題 | 介護、ケアマネ、ヘルパー、デイサービス、介護職、障害福祉 |
| `制度・報酬改定` | 制度・診療報酬／介護報酬・加算・厚労省の動き | 報酬改定、診療報酬、介護報酬、加算、厚労省、制度改正 |

**共通**

| カテゴリ名 | 内容 |
|---|---|
| `監視アカウント` | 話題ではなく「見張り対象のアカウント」の印 |

- **全投稿に話題カテゴリ（上の 10 種のどれか）を 1 つ以上付けてください。** 複数付けても大丈夫です（例: 訪問看護で生成AIを使った話 → `医療・介護×AI` と `訪問看護`）。
- **AI とも医療とも関係ない投稿（X-trend の「その他」＝一般のバズ）は集めなくて大丈夫です。** 画面にも出しません。
- `監視アカウント` だけの投稿はどの一覧にも出ません。監視対象の投稿にも、必ず話題カテゴリを一緒に付けてください。
- キーワードは例です。ノイズが多い語（「AI」「病院」単体など）は、条件を足すかどうかお任せします。
- 新しいカテゴリを足した場合も画面は自動で対応しますが、事前にオーナーへ一言ください。

## 4. 監視アカウント（`is_watched: true`）

候補（最終的にはオーナーと相談して決めてください）:

- AI 企業の公式: Anthropic、OpenAI、Google DeepMind、Meta AI、Microsoft、xAI、Mistral など
- 日本の AI 関連の発信者・メディア
- 医療・介護の発信者（厚労省、医療・介護系メディア、訪問看護の発信者など。オーナーから追加の指定があるかもしれません）

## 5. 更新タイミング

- 1 日 1 回の集計で構いません（例: X-trend と同じ **毎日 23:59 JST 集計 → 0 時台に push**）。
- 週間まとめ（`reports.json` の `weekly`）を出す場合は曜日・時刻を教えてください。
- 時刻が X-trend と違う場合も**教えてください**。画面の「次回更新」表示（`assets/js/config.js`）をこちらで合わせます。

## 6. 「伸びている投稿」とその基準

- `rising` / `rising_watch` には **AI・医療のカテゴリを持つ投稿だけ**を入れてください（話題カテゴリの無い投稿は画面側でも除外します）。
- 条件は X-trend と同じく `condition_label` の文字列で渡してください。画面はしきい値を持たないので、数値は自由に決めて構いません。
- **答え合わせの目標ライン**: X-trend は「50万表示を超えたか」（`crossed_500k`）でした。AI・医療系の投稿は表示回数が少なめなので、**目標ラインを変えても大丈夫**です。
  - その場合も**キー名は `crossed_500k` のまま**にして、真偽値の意味だけ変えてください。
  - 新しいライン（例: 10万）をオーナーに伝えてください。画面の列名「50万超え」をこちらで書き換えます。

## 7. 最初にお願いしたいこと

1. push 権限の受け取り方法（Deploy key か collaborator か）をオーナーに連絡
2. 試しに 1 回分の `data/posts.json` を push（`summary.json`・`reports.json` は後からで OK）
3. 更新時刻・目標ラインをオーナーに連絡

ご不明点はオーナー経由でご連絡ください。
